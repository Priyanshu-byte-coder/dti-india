# Paper writing guide

For whoever writes or edits the paper. It says what is final, what is still coming, where
every number comes from, and how to rebuild the Word file. Status as of **20 October 2026**.

## Ground rules

1. **The paper follows the submitted extended abstract** (`docs/extended_abstract.docx`):
   same title, RQ1–RQ4, methods and interpretation. Do not add research questions or
   change what β means.
2. **β is a conditional digital occupational wage premium, not a causal return** to
   digital skills. Keep this wording everywhere (abstract, results, discussion).
3. **No number is typed by hand.** Every number in Section 6 comes from a CSV in
   `reports/` and the tables are generated by `paper/make_tables.py`. If a number in the
   text and a table disagree, the table is right.
4. **Markers:** `[PENDING-LLM]` = waits for the full LLM run; `[PENDING-HUMAN]` = waits for
   the coder forms; `[PRELIMINARY — O*NET-transferred DTI]` = real results with the O\*NET
   measure, to be shown next to the NCO-LLM results; `[To be written …]` /
   `[Final wording …]` = text to finish once results are final. They are highlighted in
   yellow in the Word file. Remove a marker only when its content is in.
5. **Never put PLFS microdata in the repo or the paper's supplementary files.** Estimates
   and tables are fine; row-level files are not (MoSPI terms).
6. **Human coder results go in only after they pass the checks** in "Human validation"
   below.

### Rebuilding

```bash
# tables from a reports folder
python paper/make_tables.py reports/econ_onet "O*NET-transferred DTI (preliminary)" paper/tables_onet.md
python paper/make_tables.py reports/econ_llm  "NCO-LLM DTI (qwen14b)"               paper/tables_llm.md

# Word file (needs the npm package docx: `npm install docx` in any folder, then point NODE_PATH at it)
NODE_PATH=/path/to/node_modules node paper/build_docx.js paper/draft.md paper/tables_onet.md paper/DTI_paper_draft.docx
```

`<!-- TABLES:1,2,3 -->` lines in `draft.md` pull "## Table N." blocks from the tables file
given to `build_docx.js`. Once the LLM tables exist, the plan is one combined tables file
with the NCO-LLM and O\*NET columns side by side (see "After the run").

## Preliminary findings already in the draft (O\*NET-transferred DTI)

For orientation only; source `reports/econ_onet/`, tables in `paper/tables_onet.md`.

- 465,826 wage earners aged 15–64, seven PLFS rounds (2017-18 to 2023-24), 230 occupation groups.
- Premium per 1 SD of DTI: 30.4 log points raw (M1) → **5.7 (SE 1.5)** in the preferred
  M4 with division FE. Robust to weights, bootstrap, rounds, direct links only, Heckman.
- Oster δ = 0.40: weak coefficient stability → conditional association, not causal.
- Concentrated at the top: RIF 1.6 (q10) → 19.8 (q90); only the top DTI quintile earns more (13.5).
- Zero for up-to-primary education (−0.4), informal regular jobs (−0.3) and casual workers (0.9).
- Women 8.6 vs men 3.5; DTI explains none of the 31.7-point gender gap (Oaxaca −0.1).
- Rural–urban mixed (sign depends on specification).

## Pilot findings (RQ1, 50 occupations)

Main instrument: **Qwen2.5-14B with the strict rubric** (score only what the NCO text
names). Run stability ICC 0.81; 89% of non-zero scores quote words found in the text;
Spearman 0.59 with O\*NET; cross-model κ 0.83. About half of occupations score 0 on all
dimensions because NCO-2015 descriptions rarely mention digital work: this is a finding
about the official text (Section 3.1), not an error. Details in `docs/decisions.md`
("Pilot results and revised decisions").

## Human validation

- 200 occupations, stratified by division × whether the text names a digital term
  (70 keyword, 130 other), pilot occupations excluded, seed 1. Weights = 1 / inclusion
  probability, in `data/interim/validation_200_seed1.csv`.
- Three coders (C1–C3), independent, blind to LLM scores. Forms sent 20 Oct.
- Filled forms go in `data/human/` (gitignored: personal data of coders, not pushed).
- **Checks before use** (the first round failed all three): scores differ across Q2–Q6
  for a reasonable share of occupations; evidence cells contain quotes from the
  description, not numbers; coder–coder agreement is plausible (well below 99%).
  If a form fails, it is not used and the paper
  reports the validation with the coders that passed.
- Report: human–human vs human–LLM agreement (weighted κ, Krippendorff's α), unweighted
  and weighted, per dimension and for Q9; Q11 ("more digital in India today than the text
  says") as evidence on how dated the NCO text is.
